# 我的书架 (bookshelf)

> **关于本项目**
>
> 全部代码由 **AI 生成**，作者只负责提出需求、试用反馈和部署运维 —— 我不写代码，但清楚自己要什么。
>
> 做它的理由很具体：**在外面逛书店、或者准备下单之前，经常想不起来这本书到底买没买过。** 买重复了既浪费钱又占地方。所以需要一个能随手打开、搜一下就知道结果的清单。

## 为什么做这个

核心需求只有一句话：**「这本书我有没有？」**

手机打开自己的书架，搜书名，一眼看到三件事：

- 📕 **有没有实体书**
- 📱 **有没有电子版**
- ✅ **读过没有**

三个标签独立组合，正好回答「我究竟有没有这本、是哪一种」。所以它不是藏书统计工具，而是一个**随身可查的「我已拥有」清单** —— 在书店里站着、在购物车里犹豫的时候，能立刻做决定。

在此基础上才扩展出了评分、读毕日期、短评、封面墙这些让书架更好看的东西。

---

个人书架网站：管理**实体书 / 电子书 / 已读书**，书籍信息从豆瓣抓取，支持个人评分、读毕日期、短评，后台账密维护、前台只读展示。

- 技术栈：Node.js + Express 5 + better-sqlite3 + 原生 JS（无构建）
- 前台：http://localhost:5000 （实体/电子/已读三个书架 + 子筛选 + 搜索/排序）
- 后台：随机地址（首次启动打印，见下方），账密登录后维护

## 快速开始

```bash
# 需要 Node.js >= 18
npm install        # 或双击 setup.bat
npm start          # 或双击 start.bat
```

首次启动会自动生成 `config.json`（随机后台地址 + 随机初始密码），并在启动日志里打印：

```
  后台地址: http://localhost:5000/mgmt-xxxxxxxx
  账号:     admin
  密码:     xxxxxxxx!
```

端口默认 5000，被占用会自动顺延（5001、5002…）。可用 `PORT=8080 npm start` 指定。

> 数据都保存在 `data/books.db`，封面缓存在 `data/covers/`。备份 = 复制 `data/` 目录。

## 书架模型

每本书有三个独立标签，任意组合：

| 标签 | 含义 |
|---|---|
| 📕 实体有 | 有实体书，**只能手动勾选**（任何导入都不会自动标实体） |
| 📱 电子有 | 有电子文档（从本地电子书目录导入的书默认标电子） |
| ✅ 已读 | 读过 |

本地电子书导入时：**「未读书」子目录里的默认「未读」，其余默认「已读」**。

前台三个书架，每个书架内有子筛选：

| 书架 | 子筛选 |
|---|---|
| 📕 实体书架 | 全部 / 已读 / 未读 |
| 📱 电子书架 | 全部 / 已读 / 未读 |
| ✅ 已读书架 | 全部 / 电子 / 实体 / 未拥有 |

**未拥有** = 读过但实体/电子都没有（借的、网上读的、读过没买的），在已读书架里单独筛出方便补藏。
书架按我的评分从高到低排序；每张卡片显示封面、书名、作者、我的评分（1-5 星）、状态标签，点击卡片直接跳到豆瓣对应页面。

## 后台功能

登录后台后可：

1. **添加书籍**：搜索书名 → 从豆瓣结果选一个版本 → 自动带出作者 / ISBN / 封面 / 豆瓣链接 → 勾选 实体/电子/已读 + 评分。
2. **编辑 / 删除**：书架列表每本书可改可删。
3. **查找与筛选**：按书名/作者搜索，配合三个下拉：读书状态（已读/未读）、拥有状态（实体/电子/未拥有）、评价状态（已评价/未评价）。
4. **批量导入**（导入的是读书记录，默认标记「已读」）：
   - **① 豆瓣读过列表**：填你的豆瓣 ID 或主页 URL，抓取「读过」的书记录（含我的豆瓣评分、读毕日期、豆瓣短评）。上限 1000 本，中途被拦截会保留已抓到的部分。可选把豆瓣评分一起导入。
   - **② 微信读书已读完**：优先用设置的微信读书 Cookie 拉**全量**读完的书（几百本）；没填 Cookie 时降级用 `WEREAD_API_KEY` 网关，只能拉到当前书架少量书（约几十本）。
   - **③ 本地电子书目录**：递归扫描子目录里的 pdf/epub/mobi/azw3/txt，用文件名去豆瓣搜索匹配（匹配不上的标「未匹配」）。书多时需几分钟。
   - 都是先拉候选列表、勾选确认后才入库；重复的书自动跳过。
5. **设置**：豆瓣 Cookie（提高抓取成功率）、微信读书 Cookie（拉全量读完书）、默认电子书目录。

## 豆瓣抓取与反爬说明

- 无官方 API，采用页面抓取：UA/Referer 伪装 + 8 秒超时 + 失败优雅降级（可手动填写）。
- 封面不走浏览器直连，经服务端 `/covers` 代理（仅限豆瓣/微信读书域名，MD5 磁盘缓存，失败回退占位图）。
- 豆瓣反爬越来越严，未登录时批量抓「读过列表」容易 403/被拦截。在**后台 → 设置**填入豆瓣登录 Cookie（`dbcl2=...; ck=...`）可显著提高成功率。
- 请勿高频抓取，个人低频使用即可。

## 微信读书导入

两种方式，**推荐填 Cookie**：

1. **微信读书 Cookie（推荐，能拉全量）**：在「后台 → 设置 → 微信读书 Cookie」填入
   `wr_vid=xxx; wr_skey=xxx; wr_uid=xxx; wr_name=xxx`。获取方法：微信读书网页版
   `weread.qq.com` 登录后按 F12 → 网络（Network）→ 刷新 → 任意请求的请求头里复制 Cookie 字段。
   用这个能拉到全部读完的书（几百本）。
2. **WEREAD_API_KEY 网关（降级）**：环境变量 `WEREAD_API_KEY`（格式 `wrk-...`），只返回当前书架少量书（约几十本），拉不全历史读完。

## 目录结构

```
bookshelf/
  server.js             Express 主程序（路由 + /covers 封面代理 + 端口）
  db.js                 SQLite 建表与查询
  douban.js             豆瓣抓取（搜索 / ISBN / 详情 / 评分）
  auth.js               登录鉴权（scrypt + session）+ 限流
  import-douban.js      豆瓣「读过」列表导入
  import-weread.js      微信读书「已读完」导入
  import-pdf.js         本地电子书扫描 + 豆瓣匹配
  config.js / config.json  端口、secret、后台地址、初始账密
  public/
    index.html          前台（只读）
    admin.html          后台
    css/style.css
    js/main.js          前台逻辑
    js/admin.js         后台逻辑
  data/                 books.db、covers/（自动创建）
```
